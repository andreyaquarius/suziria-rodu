# Сузір’я роду

Український генеалогічний YouTube: канали, дослідники, теми, відеоджерела та сузір’я їхніх зв’язків.

Проєкт [Трекера Роду — Не губи сліди свого роду](https://trekerrodu.com.ua/).

Цей репозиторій містить лише автономну публічну версію сайту. Службова панель, база даних, повні субтитри, ключі та журнали аналізу сюди не входять. Перегляд опублікованої версії не залежить від роботи комп’ютера, на якому виконується збір.

## Перша публікація через GitHub Desktop

1. У GitHub Desktop оберіть `suziria-rodu`, перевірте список змін і натисніть **Commit to main**.
2. Натисніть **Publish repository**. Для GitHub Pages на GitHub Free зніміть **Keep this code private**, щоб репозиторій був публічним. Якщо репозиторій уже опублікований, натисніть **Push origin**.
3. На GitHub відкрийте **Settings → Pages → Build and deployment**.
4. Виберіть **Deploy from a branch**, гілку **main**, папку **/(root)** і натисніть **Save**. Додаткове збирання сайту не потрібне; файл `.nojekyll` уже включений.
5. У **Custom domain** вкажіть `suziria.trekerrodu.com.ua` і збережіть. Робіть це до додавання DNS-запису. Самого файлу `CNAME` недостатньо — перевірте налаштування Pages.

Новий репозиторій варто публікувати в тому самому GitHub-акаунті або організації, якому належить Трекер Роду. Якщо основний домен уже підтверджено в цьому акаунті, підтвердження поширюється й на його безпосередні піддомени. Якщо ні, GitHub рекомендує підтвердити володіння доменом у налаштуваннях акаунта **Settings → Pages**, додавши наданий GitHub TXT-запис у DNS.

## Піддомен в adm.tools

Підготовлена адреса: `suziria.trekerrodu.com.ua`. Якщо оберете іншу назву, узгоджено змініть `CNAME`, Custom domain у GitHub Pages та DNS-запис.

1. У [панелі adm.tools](https://adm.tools/) відкрийте **Домени → trekerrodu.com.ua → Налаштування домену (DNS)**.
2. Натисніть **Додати запис**:

   | Поле | Значення |
   | --- | --- |
   | Субдомен | `suziria` |
   | Тип | `CNAME` |
   | Дані | `ВАШ-ЛОГІН.github.io` |

   Замініть `ВАШ-ЛОГІН` на власника нового репозиторію (користувача або організацію). У значенні не повинно бути `https://`, шляху `/suziria-rodu` чи адреси `trekerrodu.com.ua`.

3. Якщо для **цього самого піддомену** вже є запис, спочатку перевірте, чи він не використовується: CNAME не може співіснувати з іншими типами записів на тому самому імені. Не змінюйте записи основного домену, `www`, пошти або NS. Не натискайте **Встановити за замовчуванням** і не створюйте wildcard-запис `*`.
4. Дочекайтеся перевірки DNS у GitHub Pages і ввімкніть **Enforce HTTPS**, коли ця опція стане доступною. Оновлення DNS та випуск сертифіката можуть потребувати до доби.

DNS-записи змінюються в панелі власника чинних NS-серверів домену. Якщо домен переведено на інші NS, налаштовуйте піддомен там.

## Оновлення матеріалів

У репозиторії зберігається зріз каталогу на момент експорту. Дата й кількість матеріалів записані в `release.json`.

Після нового збору та аналізу отримайте свіжий публічний пакет із локального застосунку, оновіть його файли тут, збережіть `CNAME`, `.gitignore`, `.gitattributes` і цей README, а потім виконайте **Commit to main → Push origin**. GitHub Pages опублікує нову версію після успішного виконання своєї процедури публікації.

Автоматичне передавання наступних локальних експортів на GitHub цим репозиторієм не налаштоване. Сам GitHub Pages не збирає й не аналізує нові відео.

Не копіюйте сюди весь локальний застосунок. У папці `data` має бути лише публічний `catalog.json`. Захисний `.gitignore` дозволяє додавати тільки очікувані файли публічного сайту; нові ресурси оформлення потрібно додавати до цього списку явно.
